## 已核实的结构差异

Weilanx 使用 React 画布和嵌套树 JSON（.wmind），Obsidian TextFileView 保存整份 JSON；Markdown 当前是导入来源，不是双向编辑的数据源。

gogoga 使用自己的 DOM/SVG 画布、树模型、Markdown 解析与保留格式的合并写回；Markdown 就是原文件，另有代码块写回、嵌入、XMind 读取及原生 Obsidian 集成。

因此，直接把 gogoga 的 main.ts 拼进 Weilanx 不等于功能融合；需要处理视图注册、命令、设置、保存、CSS、事件释放和功能适用范围。

## 三种路线

1. **完整融合（推荐，最符合原需求）**：以 Weilanx 画布为主，保留 .wmind 全部能力；引入 gogoga 的 Markdown/XMind/嵌入逻辑，并向主画布移植富内容、学习等差异能力。Markdown 使用独立读写适配层。工作量最大，但最终不是两套编辑器之间选择功能。
2. **单插件、双编辑器**：.wmind 使用完整 Weilanx，.md/.xmind/代码块使用完整 gogoga。最容易保留两边现成功能，但背诵等能力不会因此自动出现在 .wmind 编辑器中；只有用户明确接受，才能作为最终交付。
3. **以 gogoga 为主并补 Weilanx 特性**：Markdown 体验自然，但要重新补齐手绘、格式面板、分支独立结构等能力，且更容易遗漏 Weilanx 原功能，不推荐。

以下按路线 1 设计；用户可选择路线 2。路线 2 不能被描述为路线 1 已完成。

## 架构与数据流

- 一个新的插件 ID（暂定 personal-mindmap），统一中文入口、命令及设置；不覆盖原插件目录或原笔记。
- Weilanx 核心为兼容基础，新增字段采用可选扩展；原 JSON 不主动批量转换。
- Markdown 适配层保留原始文本、来源行位置及节点映射，编辑操作经过 gogoga 的保留格式写回逻辑；避免每次编辑把整篇笔记重新导出为大纲。
- Markdown 不能表达的格式不静默丢弃。跨格式转换前列出不兼容项并输出新文件；JSON 高级格式不承诺纯 Markdown 无损往返。
- XMind 读取为独立模块；转换输出新文件，不覆盖原件。不支持的数据计数并提示。
- 嵌入和完整视图共用编辑能力，事件/撤销限定在各自实例；同名代码块处理器提供开关。
- 文件保存基于编辑前快照检查外部修改。遇到冲突或解析失败保留磁盘内容并提示处理，禁止空文档覆盖。
- 视口等设备状态与笔记内容分离；学习模式临时揭晓不修改笔记；应同步的文件状态与仅本机状态分别存储。
- 插件卸载释放事件、React 根、DOM、样式、宿主补丁；多个窗格和弹出窗口互不串状态。
